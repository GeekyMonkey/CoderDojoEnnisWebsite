## Interpretation and limits

- **Confirmed gap:** the checked-in code or live metadata demonstrates a mismatch. It does not mean a production exploit was executed.
- **Decision required:** behavior differs or lacks a replacement, but reinstating it needs a product/compatibility decision. These are not automatically implementation requirements.
- **Verification required:** source/schema coverage cannot establish deployed behavior, migrated record equality or visual equivalence.
- P1 means access, data integrity or a primary workflow blocker; P2 means functional parity; P3 means convenience/presentation.
- No attendance, import, cleanup, password reset or other member-data mutation was invoked. No personal records were exported. Legacy pages were inspected as source, not run in a legacy server. This audit cannot certify that every deployed screen, storage object and external consumer matches.

## F12 implementation — 12 October 2026

The mentor sign-in route is now a logout transition to the dedicated kiosk page. Start is a verified mentor-only, same-origin operation; it registers the originating session UUID as revoked, revokes its Supabase refresh session, then issues a kiosk-only cookie. The browser signs out, resets identity, cancels/clears private queries, closes channels and performs a hard navigation replacement. The cookie is HMAC-signed using a domain-separated server secret, HttpOnly, host-only, SameSite=Strict, Secure in production and scoped to /api/Kiosk. Expiry is the earlier of 12 hours or the next Dublin midnight, including DST.

Dedicated status/end/sign-in endpoints validate kiosk authority without granting a portal identity. Password, QR and NFC sign-ins retain the four-character password rule and return scoped welcome/photo/belt/team data with contact/login/scanner fields redacted. Mentor directory stores are absent from the kiosk page; the scoped live board remains F13. Management navigation rechecks stored sessions, browser history restores revalidate protected pages, other open protected tabs discard their views on logout, and revoked JWTs are denied by protected APIs and the RLS identity helper. F03 hardware APIs and the beta legacy redirect are unchanged.

Migration f12_bounded_kiosk is applied as 20261012215451. All 213 focused tests and the production build pass. Live rollback checks verified normal mentor access, denial after revocation and restored access with a fresh session claim; no real portal session or member data was permanently changed by verification. The private registry intentionally has no client policies/grants; Supabase's informational RLS-without-policy notice reflects that design. Hosted multi-tab/Back/reload/expiry and sign-out integration acceptance remains unconfirmed.

Checklist findings and decisions now have a one- or two-word Status column after ID and Priority; the verification checklist has Status after ID because it has no Priority column.
