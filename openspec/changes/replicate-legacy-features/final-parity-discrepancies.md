# Final legacy parity sweep — 12 October 2026

Baseline: app commit `0a76125dcee12530c26baf87879219eb725db45a`; checked-out legacy source in `src_legacy/`; read-only live `coderdojo` metadata from Supabase project `newsofwpimzmfbqsooka`. This is a new audit, not a restatement of the original 33-item list. Previously completed mentor, coder and parent tasks remain completed; completed screens do not imply complete behavioral or database parity.

The sweep inventories 112 Razor templates, 28 controller files, all 100 columns in 14 legacy tables, and 85 current API route files. [Coverage and field ledger](final-parity-coverage.md), [source inventory](final-parity-source-inventory.json), [live database metadata](final-parity-database-snapshot.json), and [expected app features](../../../docs/app-features.md) provide the supporting detail.

The [role-based data-access proposal](../secure-role-based-data-access/proposal.md) addresses the database/API/realtime exposure with per-table rules and public image downloads. Security findings remain open until implementation and verification; F21 is separately closed by the accepted configuration mitigation described below.

## Interpretation and limits

- **Confirmed gap:** the checked-in code or live metadata demonstrates a mismatch. It does not mean a production exploit was executed.
- **Decision required:** behavior differs or lacks a replacement, but reinstating it needs a product/compatibility decision. These are not automatically implementation requirements.
- **Verification required:** source/schema coverage cannot establish deployed behavior, migrated record equality or visual equivalence.
- P1 means access, data integrity or a primary workflow blocker; P2 means functional parity; P3 means convenience/presentation.
- No attendance, import, cleanup, password reset or other member-data mutation was invoked. No personal records were exported. Legacy pages were inspected as source, not run in a legacy server. This audit cannot certify that every deployed screen, storage object and external consumer matches.

## F21 closure note — 12 October 2026

**Closed by user-accepted configuration mitigation.** The user set the hosted Supabase Data API Max rows setting to **1,000,000** (one million, superseding the earlier ten-million request) and explicitly accepted closing F21 with a note. Retain existing paging where present; revisit F21 if any relevant result set approaches the configured cap, the setting changes, or response size/timeouts prevent reliable full results. Future project provisioning must preserve this setting or reassess the mitigation. Other access, history and date findings remain open.
