# Public Projects destination audit — 2026-10-15

Audited live public API data and every destination generated by the Vue Projects directory in feature commit `348c605` (PR #69, merged 2026-10-14). No application or directory data changed.

## Findings

- **21 entries:** 14 coders and 7 mentors. **2 working root sites; 19 genuine GitHub Pages HTTP 404s (90.5%).** All 21 GitHub accounts returned HTTP 200; none is an account-deletion result.
- All 19 failed root sites returned GitHub’s own “Site not found” page, and their matching `<login>.github.io` repository API returned 404. This is stronger evidence than a timeout or bot block, although repository 404 alone cannot distinguish absent/private repositories.
- **6 alternative project paths returned HTTP 200**, with project-specific titles and public repositories advertising GitHub Pages. Recommended updates below require choosing a featured project; do not apply silently.
- Current live `/projects` returns a generic Nuxt application shell, not SSR directory markup. Therefore this audit does not claim the migration is deployed. The deployed `/_members.html` Angular fragment and develop legacy script generate the same root URLs as the migration. This is a pre-existing destination/data issue.
- Canonical `https://coderdojoennis.com/api/githubaccounts` succeeded with curl; `www.coderdojoennis.com` failed DNS in this environment. GitHub checks used Python urllib with a descriptive User-Agent. HTTP GETs followed redirects; none of the 21 roots redirected.

## Data-source issue and recommended next change

The [live API](https://coderdojoennis.com/api/githubaccounts) exposes names and GitHub logins, not project URLs. [PublicDirectoryEntry.vue](../../src/app/components/Public/PublicDirectoryEntry.vue) blindly derives `https://${GithubLogin}.github.io`; [usePublicDirectoryStore.ts](../../src/app/stores/public/usePublicDirectoryStore.ts) validates username syntax, not publication. [githubaccounts.get.ts](../../src/server/api/githubaccounts.get.ts) selects active coder/mentor members with a nonempty GitHub login and never checks Pages publication. A GitHub account does not imply a root GitHub Pages site; project sites can live only at `/<repository>/`.

Recommended design: maintain explicit, verified project URL(s), distinct from GitHub profile identity; display only configured project links and optionally a separately labelled GitHub profile link. Record a last-verified timestamp and recheck periodically. A one-time root-site filter would hide the six reachable path-based projects above. User approval is required before choosing destinations/removing public entries.
